# DeepSeek Harness 人物化 Agent 界面设计

## 1. 目标

将现有 DeepSeek Harness 从传统聊天工作台改造为“人物完全代表 Agent”的互动界面。短期交付可运行的分层 PNG 角色，长期替换为正式 Live2D 模型；两者复用同一套 Agent 状态、动作语义和界面结构。

质量优先，允许使用合理的付费工具或专业服务，但任何实际购买、订阅、授权或外包必须先向用户说明费用与用途并取得确认。

## 2. 非目标

- 不修改 DeepSeek 模型本身，也不把人物动画放入低层工具执行逻辑。
- 不为了人物化而删除 Harness 的历史任务、项目、模型、权限、设置或完整输出。
- 不在短期 MVP 中实现语音合成、实时口型、好感度、长期角色记忆或复杂换装。
- 不直接把不可复现的手工改动散落在 `node_modules` 中作为最终交付。

## 3. 产品原则

1. 人物是唯一的 Agent 视觉主体，不是聊天框旁的装饰宠物。
2. 默认界面只突出人物、任务泡泡、说话气泡和输入区域。
3. 人物说话气泡提供精简答案，完整信息必须可以一键查看且不得丢失。
4. 动作来自真实 Agent 状态；随机动作只能用于待机表现。
5. 动画克制、自然、可关闭，并支持系统减少动态效果设置。
6. 所有原有能力必须保留，只改变入口和表现形式。
7. 角色渲染器可替换，短期分层 PNG 不得锁死长期 Live2D 路线。

## 4. 视觉与空间布局

### 4.1 视觉世界

采用“深海研究室”方向：海盐白、深海蓝和少量紫色光效。背景清透、低噪声，人物保持最高视觉饱和度。装饰元素限于克制的水波、气泡、声呐环和推理核心光效。

### 4.2 主界面

- 顶部：窄顶部栏，容纳用户信息、设置、模型、权限及必要的全局状态。
- 中上部：人物主舞台，占桌面可用高度约 65% 至 72%。
- 人物周围：有限数量的任务泡泡。
- 中下部：人物说话气泡，位置随镜头和遮挡安全区调整。
- 底部：Codex 风格的长矩形输入区，使用 16 至 20 像素圆角，不使用药丸形外观。

### 4.3 任务泡泡

- `+` 泡泡创建新对话或新任务。
- 普通泡泡显示任务、对话或项目名称，点击后进入对应内容。
- 当前任务使用克制但明确的选中状态。
- 桌面端最多显示 4 至 6 个任务泡泡；窄屏进一步减少。
- 超出数量后显示 `…` 泡泡，点击打开可搜索、可选择的完整任务列表。
- 泡泡必须避开人物脸部、手部主要动作区、说话气泡和输入区。
- 任务泡泡与人物说话气泡使用不同轮廓、尺寸和层级，避免误认。

### 4.4 精简输出与完整输出

- 简单结果显示一句话。
- 复杂结果最多显示三条短句。
- 点击说话气泡后进入“专注阅读层”。
- 阅读层支持 Markdown、代码块、表格、工具调用记录、复制、滚动和收起。
- 阅读层打开时，人物与舞台模糊并降低亮度，底层交互进入 `inert` 状态；后台 Agent 默认继续运行。
- 收起阅读层后恢复人物镜头、最新状态和输入焦点。

## 5. 人物镜头与交互

镜头采用缓慢自适应策略：

- 待机：接近全身构图，展示鲸尾、服装和道具。
- 用户输入：人物轻微靠近，目光转向输入区域。
- 思考：转换为更清楚的中景，但禁止突然放大。
- 输出：保持中景并让目光偏向说话气泡。
- 完成后：缓慢回到待机镜头。

所有镜头变化使用可中断的缓动或弹簧过渡。状态切换时应从当前位置继续，禁止先跳回初始帧再播放新动作。

## 6. 状态与动作矩阵

| 状态 | 主要表现 | 鼠标视线 | 可否随机动作 |
| --- | --- | --- | --- |
| `idle` | 呼吸、轻微重心移动、自然眨眼 | 缓慢跟随 | 是 |
| `user_input` | 苏醒、前倾、目光转向输入区 | 输入区优先 | 否 |
| `thinking` | 目光上移或侧移、推理核心脉动 | 暂停 | 否 |
| `streaming` | 看向说话气泡、轻微嘴型和手部动作 | 气泡优先 | 否 |
| `tool_running` | 专注表情、显示对应工具小道具 | 暂停 | 否 |
| `waiting_user` | 期待表情、身体轻微前倾 | 看向用户或输入区 | 否 |
| `success` | 微笑、鲸尾轻摆、少量庆祝气泡 | 短暂看向用户 | 否 |
| `error` | 担忧表情、推理核心短暂变暗 | 暂停 | 否 |
| `sleeping` | 闭眼、头部轻垂、呼吸减慢 | 禁用 | 否 |
| `waking` | 睁眼、重新聚焦、短促伸展 | 逐步恢复 | 否 |

状态优先级由明确事件驱动，重要状态可中断待机动作。动作结束后重新读取当前 Agent 状态，禁止盲目返回旧状态。

## 7. 待机随机动作与睡眠

- 自然眨眼使用轻微随机间隔，避免固定节拍。
- 特殊待机动作包括捋头发、轻摆鲸尾、调整站姿和短暂看向远处。
- 调度器设置动作权重、冷却时间和“不连续重复”规则。
- 连续无输入约 150 至 210 秒后进入睡眠，具体时间在区间内随机。
- 鼠标移动不唤醒睡眠人物。
- 用户聚焦输入并产生 `beforeinput` 或等效真实输入事件时立即进入 `waking`。
- 苏醒动作不得阻塞用户输入或延迟消息发送。
- 页面不可见时暂停非必要动画与定时器；恢复可见时重新计算状态，不补播离线期间的动作。

## 8. PNG 到动态人物的素材流程

### 8.1 母版与分层

以 `ai-anime-girl-deepseek-v2.png` 为视觉母版，保留原图不覆盖。建立可长期维护的分层 PSD，至少包含：

- 后发、前发、侧发和可独立摆动的发束。
- 脸部底图、左右眉毛、眼白、瞳孔、高光、上下眼皮。
- 闭嘴、微笑、说话、担忧等基础嘴型或表情层。
- 头、颈、躯干、肩、上臂、前臂、手和必要的服装覆盖层。
- 披肩、外套、裙摆、腿、靴子、鲸尾。
- 推理核心、发饰、胸针、水波、气泡和声呐光环。

每个可移动部件必须补全原图中被遮挡的区域并保留足够重叠。AI 分割和生成式补画只作为初稿，人物脸、眼睛、手、卷发接缝、服装边缘和鲸尾连接必须人工级复核。

### 8.2 短期 2.5D 渲染

- 使用透明 PNG 图层和遮罩组合人物。
- 瞳孔在眼眶蒙版内移动，实现有限角度的慢速视线跟随。
- 上下眼皮控制眨眼和睡眠闭眼。
- 嘴型使用有限纹理切换，不实现实时语音口型。
- 发束、衣摆和鲸尾通过锚点、弹簧和阻尼产生轻微惯性。
- 身体与镜头使用独立变换，避免把所有运动叠加到同一节点。
- 导出人物图层清单、层级、锚点、碰撞安全区和参数范围的机器可读清单。

### 8.3 长期 Live2D

- 将同一分层 PSD 导入 Live2D Cubism Editor。
- 使用 ArtMesh、旋转变形器和弯曲变形器制作头部、眼睛、眉毛、嘴、身体和肢体参数。
- 使用物理系统驱动头发、披肩、裙摆和鲸尾。
- 建立 Motion、Expression、Pose 和 Physics 数据。
- 使用 Cubism SDK for Web 实现正式运行时。
- `CharacterController` 保持不变，仅把短期渲染器替换为 `Live2DRenderer`。

## 9. 软件架构

```text
Harness 会话、消息、工具和输入事件
                 |
                 v
        HarnessStateAdapter
                 |
                 v
        CharacterController
        |        |        |
        |        |        +-- IdleActionScheduler
        |        +----------- GazeController
        +-------------------- MotionCoordinator
                 |
        CharacterRenderer 接口
          |                  |
          v                  v
 LayeredPngRenderer     Live2DRenderer
```

### 9.1 模块职责

- `HarnessStateAdapter`：把 Harness 的真实状态映射为稳定的角色状态，不包含动画细节。
- `CharacterController`：处理状态优先级、进入与退出动作、抢占和恢复。
- `IdleActionScheduler`：只在待机状态调度随机动作与睡眠。
- `GazeController`：平滑鼠标目标、输入区目标和说话气泡目标。
- `MotionCoordinator`：合成身体、脸、道具和镜头动作，解决冲突。
- `CharacterRenderer`：统一参数接口，隔离分层 PNG 与 Live2D 实现。
- `TaskBubbleController`：管理任务泡泡可见数量、布局、安全区和完整列表入口。
- `ReplyPresenter`：保存完整输出，生成精简展示并控制阅读层。

## 10. 开发与安装边界

- 主源码、设计、素材和测试保存在独立工程中，由 Codex 负责集成与版本控制。
- DeepSeek Harness 用于真实状态验证、交互体验和自测，不作为唯一开发环境。
- 优先调查 Harness UI 插件或插槽能力；若不足，再使用版本受控、可回滚的安装补丁。
- 安装器在修改前记录 Harness 版本并备份目标文件。
- Harness 升级后若版本不兼容，人物模块必须安全停用并恢复原生 UI，而不是继续注入未知代码。

## 11. 错误处理与降级

- 人物素材加载失败：显示静态母版或原生 Harness 界面。
- 渲染器初始化失败：停止动画但保持输入、任务切换和完整输出可用。
- 状态事件缺失：回退到 `idle`，不得伪造工具执行或完成状态。
- 精简摘要失败：显示经过长度限制的原始回答开头，并保留完整输出入口。
- GPU/WebGL 不可用：回退到分层 DOM/Canvas 或静态模式。
- 页面性能下降：依次关闭粒子、物理次级动作、镜头动效，最后保留状态表情。

## 12. 性能与可访问性

- 目标桌面端动画保持稳定 60 FPS；低性能设备允许 30 FPS 降级。
- 页面隐藏时暂停动画循环。
- 避免高频 React 状态更新；逐帧动画留在渲染器内部。
- 支持 `prefers-reduced-motion`，并提供关闭、轻柔和完整三档设置。
- 所有任务泡泡、说话气泡和顶部栏功能支持键盘访问与明确焦点样式。
- 人物装饰动作不进入屏幕阅读器播报；状态变化使用克制的 `aria-live`。
- 专注阅读层和完整任务列表必须锁定焦点，关闭后恢复原触发点。

## 13. 测试与验收

### 13.1 功能验收

- 新建、切换、搜索和恢复任务不丢失 Harness 原有数据。
- 用户输入、思考、流式输出、工具执行、等待、成功、错误和睡眠均来自真实事件。
- 精简气泡与完整输出内容一致，不得捏造结论。
- 完整输出支持代码、表格、长文本和工具记录。
- 用户开始输入时人物可立即从睡眠唤醒，输入不被动画阻塞。

### 13.2 视觉验收

- 人物脸部、头发、手和鲸尾移动时没有透明洞、接缝、重影或拉伸破绽。
- 视线跟随缓慢、有边界，不出现翻白眼或高频追踪。
- 人物、任务泡泡、说话气泡和输入区在 1440、1024 和 390 像素宽度下不遮挡关键操作。
- 动画状态变化明显但不过度，连续工作十分钟不造成持续视觉干扰。

### 13.3 回归与升级验收

- 原生新会话、工作区、设置、模型、权限和工具执行仍可用。
- 控制台无新增错误，关键状态 E2E 报告为空。
- 安装、卸载和回滚流程均经过真实执行验证。
- Harness 版本不兼容时能安全回退，不出现无法启动的情况。

## 14. 费用策略

- 免费或现有工具可以达到质量目标时不额外购买。
- Live2D Cubism PRO、Photoshop 素材分离插件所需授权、专业绑模或局部补画外包均属于候选费用。
- 任何付费动作必须先提供用途、预计金额、替代方案和对质量或周期的影响。
- 在公开发布或商业化前，重新核对 Live2D SDK、编辑器、素材和第三方运行时许可。

## 15. 分阶段交付

1. Figma 完成桌面、窄屏和关键状态原型。
2. 生成角色素材分层清单与补画说明。
3. 制作分层 PSD 和透明图层，完成静态拼装验收。
4. 实现独立的状态适配器与角色控制器测试。
5. 实现短期 `LayeredPngRenderer` 和动作矩阵。
6. 接入任务泡泡、输入区、精简回复和专注阅读层。
7. 制作可回滚安装器并执行 Harness E2E。
8. 使用 Cubism 完成正式 Live2D 绑模与物理。
9. 替换为 `Live2DRenderer`，复用已有控制器并完成回归验收。

## 16. MVP 完成定义

短期 MVP 只有在以下条件全部满足时才算完成：人物在真实 Agent 状态下产生对应反应；可进行新建和切换任务；用户能够输入并查看精简与完整输出；睡眠与输入唤醒可复现；静态和动态降级可用；原生 Harness 关键功能无回归；安装、卸载和重启后均通过验证。
